# 夸一夸小程序产品方案 v1.0

日期：2026-09-28  
用途：产品立项、范围评审及后续原型与需求设计依据。  
状态：已确认产品方向的方案稿；已产出用户端网页交互原型，正式小程序及真实用户验证尚未开展。  
本轮更新：确认微信登录方式与游客、取消、失败、登录后续接流程（见第五节第 6 部分）；海报生成提示词见第六节。

## 一、产品定位与立项目标

**一句话定位：上传照片，写下一句话，把日常经历变成一张懂你、值得分享的夸夸海报。**

产品为用户提供两层价值：当下得到具体、自然的理解与肯定；长期通过用户确认的个人和家庭经历、偏好，让后续回应更贴近本人。

首期以微信小程序作为产品形态，独立于云忆回忆录开展体验、运营和商业验证。用户无需建书、完成采访或填写完整个人档案。

### 本轮已确认

1. 宝妈、职场人、学生、长辈、日常五类同等投入，均纳入首发；不将宝妈设为唯一主场景。
2. 不同分类对应不同的回应策略和提示词。
3. 每个账号拥有独立的个人／家庭知识库，在使用中逐步积累，经用户确认后保存，也可主动补充。
4. 主流程保持照片加一句话生成海报；分类收至“我的”，不设珍藏；底部导航为首页、夸夸集、我的。
5. 首期重点验证用户认可、分享和再次使用，同时提供限次数的包月套餐。

本方案中的具体额度、价格展示方式、页面命名与套餐周期细则属于产品建议；与以上已确认方向区分。没有现成用户研究、转化数据或生成成本证据，文中价值判断属于待验证假设。

## 二、用户与使用场景

| 人群分类 | 使用时刻 | 用户输入示例 | 希望获得的价值 | 回应侧重 |
|---|---|---|---|---|
| 宝妈 | 亲子陪伴、孩子成长、育儿感受、自己的小成就 | 今天陪女儿学会了骑车，跑得我满头汗 | 孩子的成长有记录，自己的感受也被看见 | 具体陪伴与成长；不过度赞美牺牲 |
| 职场人 | 完成工作、突破难题、学习技能、下班时刻 | 忙了两周，方案终于通过了 | 认可努力，留下阶段成果 | 具体行动与进步；不美化过劳 |
| 学生 | 学习、考试准备、校园活动、毕业 | 今天终于把这道题弄懂了 | 得到鼓励，看到自己的成长 | 尝试、理解与探索；不制造比较 |
| 长辈 | 兴趣、旅行、朋友相聚、新体验 | 第一次登台唱歌，有点紧张但很开心 | 表达生活热情与自信 | 平等肯定生活选择；不制造年龄反差 |
| 日常 | 做饭、养花、宠物、运动、旅行 | 第一次做面包，样子一般但很好吃 | 发现普通生活的趣味和用心 | 自然、有细节、可适度俏皮 |

五类同等投入落实为：入口展示权重一致、首期功能一致、每类有独立提示词与样例、每类做同等覆盖的体验验证，并分别观察数据。分类是本次表达场景，不是账号永久身份；同一个人可跨分类使用。

## 三、核心价值设计

### 1. 操作轻

进入后上传照片、写一句话即可生成；夸赞场景默认宝妈，在“我的”里设置；不要求先建立个人档案，不增加风格、情绪、对象等多层必填选择。

### 2. 回应具体

围绕用户真实经历和照片细节，指出值得肯定的行动、感受或用心。开心时分享开心，疲惫时先接纳感受，不将所有输入变成相同的正能量口号。

### 3. 成果能分享

最终交付完整海报，包含用户照片、标题、简短正文、日期和克制的产品标识。照片与表达是主体，支持直接预览、保存和分享。

### 4. 逐渐懂本人

分类决定回应角度，知识库提供相关背景，本次输入始终决定内容主体。用户可以知道产品记住了什么，并修改或删除这些资料。

## 四、产品结构与功能范围

底部设置三个常驻 Tab：首页、夸夸集、我的。夸夸集用于展示本人制作中、已完成与失败的海报，与“使用记录”（次数流水）区分。首页顶部不再显示“夸一夸”品牌字、英文副标或头像，保留右上微信胶囊。三个主页面显示底栏；套餐、使用记录等二级页面采用返回导航。底栏适配手机安全区，不遮挡末尾内容；输入键盘展开时避让。我的页顺序为头像信息、紧凑次数卡片、美好打卡摘要、夸赞场景、使用记录；不重复设置夸夸集入口，不显示“我的日常”分组标题；使用记录仅显示名称，不显示副说明或下方寄语，套餐从卡片进入。美好打卡、夸赞场景、使用记录统一为约 78px 高的无底色列表行，左侧同规格图标，右侧箭头，底部细分隔线；夸赞场景右侧保留当前分类名称。

我的页可用次数卡片采用浅米白木桌、便签和雏菊背景，左侧显示真实可用次数、额度构成及有效期，右上显示“查看套餐”，整卡进入套餐页。数字保持紧凑（约 32–36px），不替换成回忆数量或赞赏数据。夸赞场景入口左侧使用固定通用图标，右侧显示当前选择的人群；选择弹窗内保留五类各自图标。

| 模块 | 用户功能 | 首期规则 |
|---|---|---|
| 创作首页 | 照片上传、一句话输入、生成、最近的夸夸 | 1–6 张照片；至少一张与非空配文；切换分类不丢输入 |
| 制作状态 | 查看进度、离开后找回、失败重试 | 使用真实状态，不设置虚假的自动完成倒计时 |
| 海报结果 | 预览、保存、分享、返回修改 | 展示可分享的完整成品；重新生成保留旧成果 |
| 夸夸集 | 查看制作中、失败、已完成内容 | 不另设珍藏；记录可删除；已完成海报点击即预览和分享 |
| 美好打卡 | 连续天数、最近七天与今日状态 | 每天成功生成至少一张海报自动打卡，无手动签到或额外扣次 |
| 关于我 | 管理本人／家人、偏好、经历 | 空资料可用；支持查看、补充、修改、停用和删除 |
| 套餐与次数 | 查看剩余次数、有效期、购买、消费记录 | 提供有限免费体验与限次数包月套餐 |
| 反馈与设置 | 反馈回应问题、管理资料使用、账号设置 | 可反馈“太空泛”“不符合事实”“不喜欢这种表达”等 |
| 运营管理 | 分类内容、提示词、海报模板、套餐、订单、任务与效果统计 | 各类独立维护和评估，用户不需要自己写提示词 |

首页不展示宝妈、职场人、学生、长辈、日常的分类入口，也不设置“全部”。分类收至“我的 → 夸赞场景”，默认“宝妈”，五个选项可随时切换，按账号记住选择并用于后续生成。切换场景只更新生成偏好，不清空照片或配文，不改写历史海报。旧账号已明确选择的分类继续保留；旧版“全部”默认值迁移为“宝妈”。五类人群投入保持同等。首次打开不预填示例照片或配文，已有草稿继续保留。首页不展示次数、个人资料完成度、成长等级或复杂任务卡。

首页以 2026-09-29 14:49 用户参考图为当前视觉方向：顶部湖景、花枝与咖啡杯大图通铺，图内保留两行手写“发现美好／记录美好”和副文案；下方圆角暖白面板承载真实创作操作。删除旧独立上传大卡、底部花草装饰、输入框上方“说说这一刻...”标题。输入提示只保留“分享此刻的故事…”。排列为文本输入框、右对齐 0/300 字数统计、已添加照片、整行“添加照片”按钮；照片区域按缩略图实际高度排列，与继续添加入口间距约 10px，不沿用大图容器比例。添加入口高度至少 50px，点击展示“从相册选择”“拍照”“取消”；相册可多选，拍照每次一张，累计最多 6 张；取消不丢原照片和文字。达到上限后显示已添加 6 张并禁用添加，删除后恢复。生成按钮只保留“夸一夸，生成海报”文字。当前浏览器以文件选择器和 capture=environment 接入拍照入口，实际相机调用受手机浏览器支持影响；正式小程序通过媒体选择能力实现相册和拍照，取消、拒绝或失败均保留草稿。


### 首页最近的夸夸

生成按钮下方展示“最近的夸夸”，按提交时间倒序最多显示 10 份；卡片包含本次照片封面、简短标题或本次配文、日期。单行展示 2 个完整卡片和第 3 个的半张，向左滑动浏览后续内容；采用紧凑横版缩略图、单行标题及日期，制作中／失败状态叠加在缩略图上，不再设置独立的卡片底部操作栏。“查看全部”进入夸夸集。已完成卡片使用原照片作为封面，点击打开完整海报图片弹窗，直接下载或分享，不增加中间详情跳转。制作中卡片显示状态，点击查看进度；失败卡片进入保留原输入的重试详情。无记录时显示“还没有夸夸海报”和“生成后，在这里回看与分享”。游客不展示其他账号的历史记录；查看全部时按既有微信登录规则引导。生成完成后刷新当前账号的最近内容；保存、分享与预览均不扣次数。

### 美好打卡

功能名称“美好打卡”，核心表达“连续记录 X 天”。在夸夸集顶部用约 140px 高的紧凑卡片展示连续天数、最近七天及今日状态，未打卡时“去记录”与连续天数同排；不展示“累计 X 天 · 最长连续 X 天”；我的页显示摘要并可进入夸夸集。

- 以北京时间自然日计算，海报成功生成的完成时间为归属日期，跨午夜完成计入次日。每天首次成功自动打卡，多次生成只记一天，多张照片合成一张也只记一天。
- 制作中、失败、仅上传、预览、保存和分享不计打卡；失败重试成功后，按重试完成日期计入。
- 今天已完成显示“今日已打卡”；今天尚未完成但昨天有打卡时，保留截至昨天的连续天数并显示“今天生成，延续美好”。昨天也没有打卡则当前连续归零；下一次成功从 1 天开始。
- 不提供补签、排行榜、奖励次数或额外付费打卡。未打卡时可点击“去记录”返回首页，仍使用原生成流程与额度规则。
- 打卡按账号隔离、持久保存，删除海报不删除已获打卡；旧账号已有成功记录按完成日期迁移。累计天数和最长连续不因中断归零。
- 正式小程序由服务端生成成功事件原子写入打卡，以账号与业务日期唯一约束去重；使用服务端北京时间，不以客户端时钟或按钮点击为准。当前浏览器原型只模拟此规则。恢复前台或跨天后更新展示。

## 五、关键使用流程

### 1. 首次生成

进入首页 → 按账号场景偏好上传照片并写一句话 → 首次提交时微信登录 → 校验可用次数并提交制作 → 在“夸夸集”查看 → 保存或分享。

可先编辑再登录；取消或失败保留照片、分类与文字，不创建任务或扣次。首次不要求整理知识库；首页不增加次数提示。登录成功后继续原来的提交动作。

### 2. 再次使用

进入首页 → 使用已保存场景并输入 → 按用户授权参考相关个人资料 → 制作海报 → 查看、保存或分享。

有可用资料时可显示轻量“结合我的资料”开关；关闭后仅依据本次输入生成。不能强迫用户使用知识库才能获得完整海报。

### 3. 制作等待与恢复

海报生成须先处理照片，再进行图文排版：逐图识别主体、场景与安全区域，按需裁切、主体提取或清理干扰背景，统一曝光和色温；保留人物身份、原动作和重要物件。环境有意义的图片保留场景，不要求每张都抠图。处理结果始终绑定原照片索引，避免夸赞串图。再按内容、照片比例和信息量安排主图与辅助图，不能直接把原图塞进等大格子。处理失败或主体识别低信心时，保留完整照片，不静默丢弃。最终输出前检查主体完整、图文对应、文字可读与整体构图。

海报默认横版 3:2。单图按主体和照片比例安排图文关系；多图逐张识别，并针对每张照片分别生成夸赞，以“照片＋对应夸赞”成组排版，最终合成一整张横版海报。用户填写的一句话是整组照片的背景信息，不能当作每张照片都发生了同一件事；每张夸赞依据该照片可见内容和适用背景，不推断无法证实的经历。照片与夸赞数据按上传顺序编号；视觉布局可安排主辅，但必须保持编号对应，夸赞不得串图、遗漏或套用同一段总评。1–6 张照片最终均只产出一张海报、计 1 次，预览、分享与保存尺寸一致。

提交成功后弹出“已收到，海报预计 5 分钟做好。可以先离开，稍后在「夸夸集」查看。”，提供“查看进度”和“继续记录”。不设置独立制作中页面；“夸夸集”显示照片缩略图、制作中状态与提交时间，完成后点击列表图片或记录文案，以弹窗展示完整海报，提供下载与分享；关闭后保持原列表和筛选状态。支持系统文件分享时调起系统分享面板，不支持时提示先下载图片再分享。失败保留原输入并允许重试，重试同样返回记录列表。不给出倒计时或百分比，不打断用户正在进行的另一项创作。微信小程序阶段可提供用户主动订阅的完成提醒，当前网页原型不提供虚假的订阅按钮。

### 4. 知识积累

海报完成后提供不打断操作的“记住这件事”入口，也可在记录详情中进入 → 从用户原始配文整理候选内容 → 用户确认涉及谁、记住什么及使用范围 → 加入个人知识库。

保存海报、分享和购买均不以确认知识入库为前提。系统推荐记忆内容，但不能静默保存，也不能把 AI 夸赞转成用户事实。

### 5. 套餐购买

免费次数用完或包月次数耗尽 → 展示已有输入和套餐权益 → 用户主动购买 → 返回原创作内容继续制作。不能先展示已生成的完整成果，再临时要求付费解锁。

### 6. 微信登录与账号归属

**已确认采用微信登录。** 产品侧提供“微信登录”按钮；“授权登录”表示用户主动建立账号，不把微信身份登录、获取手机号、填写头像昵称或资料公开授权混为一项。主引导发生在用户点击“夸一夸，生成海报”后：先检查照片和配文，再在当前首页弹出微信授权引导，成功后自动提交制作，不跳到独立登录页，也不要求再点一次生成。浏览首页、上传照片和写文字均不提前弹出授权；“我的”只保留用户主动登录的入口。

| 场景 | 页面及行为 |
|---|---|
| 游客进入首页 | 选照片与填写文字可操作，默认使用宝妈场景；分类在“我的”中设置 |
| 首次点击生成 | 先检查照片和配文；有效后在首页弹出授权引导，主按钮“微信授权并生成”，可关闭或“暂不生成” |
| 点击“我的” | 未登录时显示登录入口和“先去记录这一刻”；不展示其他账号的记录、资料或额度 |
| 直接打开记录、资料、套餐或使用记录 | 未登录先展示登录入口；成功后回到原目标页 |
| 登录中 | 按钮显示“正在登录…”，禁止重复提交，仍可取消；取消后晚到的结果不自动创建任务 |
| 登录取消或失败 | 保留草稿；失败提供重试；不预占次数，不创建制作任务 |
| 登录成功 | 返回原目标；从生成动作发起时继续提交一次，从“我的”进入时只展示账号页面 |
| 已登录再次使用 | 有效会话直接使用；会话失效先尝试正常恢复，恢复失败再提示登录，保留当前草稿 |

生成时弹窗文案：标题“生成前，先微信授权”；说明“授权登录后，这张海报和制作记录会保存在你的账号里。”；主按钮“微信授权并生成”，次操作“暂不生成”；补充“使用微信身份建立账号，无需填写手机号”。不自动拉取或承诺读取微信头像昵称，未完善资料时使用默认头像和昵称，不影响制作。

**账号与草稿：**

- 服务端以微信小程序身份映射内部账号；首次创建账号仅发放一次 3 次免费体验。重复登录、重装或换设备登录同一账号不重复发放。

### 4. 正式接入流程与阶段输出

服务端验证账号、额度和输入 → 固定输入与提示词版本 → 逐图理解并生成文案 → 内部校验 → 图片处理与整体合成 → 成品检查 → 标记完成。

**阶段一：逐图理解、文案生成与校验。**

- 生成一份整体标题，以及与每张照片绑定的独立夸赞。
- 内部记录逐图可见事实、配文中适用的背景和建议保留区域，用于事实核验与后续图片处理；这些说明不展示在成品上。
- 输出至少包含 `title` 和 `photo_items`；每项包含 `photo_id`、`praise`、`visible_facts`、`processing_notes`。照片编号与上传列表一一对应，不能用单段 `body` 代替多张照片的夸赞。
- 在进入生图前校验事实依据、照片数量、对应关系、隐私、分类语气和文字长度。不通过则修正当前阶段，不将未校验文案交给生图模型。
- 校验为内部步骤，不增加用户确认文案的必填流程。

**阶段二：图片处理与横版合成。**

向图像模型传入原图、稳定照片编号、已校验的整体标题与逐图夸赞、必要的处理说明、日期和视觉约束。沿用总提示词的图片处理、整体设计与输出检查要求，并追加：

**状态与计次：**沿用预计约 5 分钟、提交后可离开与记录中找回的流程；1–6 张照片最终合成一张海报，成功只计 1 次。内部文案修正、图片处理重试和合成恢复不创建新的用户收费任务。预览、下载和分享使用同一份完成态成品。

### 5. 版本、验收与实现边界

后台支持通用规则、分类规则、图片处理与合成规则的编辑、样例预览、发布和回退；每次任务固定所用版本。已经生成的历史海报不随提示词发布而改写。

| 验收范围 | 通过标准 |
|---|---|
| 五类表达 | 五类均覆盖正向事件、普通日常、疲惫失落、资料冲突；不能只验收宝妈样例 |

## 七、个人与家庭知识库

面向用户命名为“关于我”，避免首次使用时增加“搭建知识库”的理解负担。

| 内容 | 示例 | 使用价值 |
|---|---|---|
| 我与家人 | 我、女儿、父亲及用户填写的称呼 | 分清经历属于谁，避免张冠李戴 |
| 兴趣与表达偏好 | 喜欢做饭；喜欢自然的文字；不喜欢夸张称呼 | 调整语气和关注点 |
| 经历与小进步 | 开始练习跑步；最近陪女儿学骑车 | 在相关场景下更好理解当前记录 |

### 积累与使用规则

1. 首期来源为用户主动录入，以及使用后确认保存的经历。
2. 当前照片和配文优先于旧资料；冲突时不采用旧事实，不擅自更新个人档案。
3. 点击某个人群分类不自动写入身份事实；上传合照不自动建立家庭关系。
4. 本人与每位家人的资料分开；每次只参考有关内容。
5. 生成文案不自动入库，失败制作也不自动增加经历。
6. 用户可查看、修改、停用、删除，并可关闭本次资料使用。
7. 资料默认只供本人使用，账号之间互不读取，不默认同步云忆资料。

### 记住与公开是两件事

资料可分为“不用于生成”“仅帮助理解、不主动写出具体事实”“允许引用到海报文案”。系统不能因为知道姓名、学校或过往经历，就自动加入公开海报。

分享前展示最终海报。删除资料后不再用于后续生成；已保存或分享出去的图片不会随之撤回。

- 首期建议无加购包和多套餐叠加；次数耗尽或到期后均可购买下一期。提前耗尽后购买，新一期从本次购买成功起计算 30 天，旧期限不叠加；购买前明确展示新的次数和到期时间。仍有可用次数且未到期时不引导重复购买。
- 套餐到期未用次数不结转，购买前明确展示。到期前已受理的任务继续完成；其失败重试不要求为同一任务重新购买。
- 免费次数与套餐次数并存时，优先使用先到期的套餐次数；消费记录展示扣次来源，避免误解。
- 采用用户主动购买，不默认自动续费。到期后保留知识库和历史成果，套餐只影响新制作额度。

### 4. 订单与售后

展示购买记录、付款状态、有效期和次数使用记录；重复点击或支付回调不应产生重复订单或重复权益。退款入口与规则在上线前随价格方案一并明确，争议扣次能查证和处理，不在本稿未经确认地承诺不可退或自动退款。

## 九、运营与管理能力

| 管理对象 | 产品需求 |
|---|---|
| 人群分类 | 展示名称、输入提示、排序与状态；五类均具备上线内容 |
| 分类提示词 | 独立编辑、测试样例、效果对比、发布与回退 |
| 海报模板 | 单图／多图版式、文字容纳、品牌标识；首期少量统一风格 |
| 知识使用问题 | 用户反馈与纠错入口，避免要求运营日常查看私人资料 |
| 制作任务 | 状态、失败原因、用户问题定位与次数返还核对 |
| 套餐与订单 | 售价、次数、周期、订单查询、权益异常处理 |
| 产品效果 | 分人群观察使用、满意反馈、保存分享、复用与付费 |

五类同等投入不意味着长期忽略数据：首轮采用一致的覆盖标准，后续再依据实际结果调整策略；本方案不预先收缩任何一类。

## 十、首期范围与迭代

### 首期必须具备

- 五类人群完整可用及分类提示词。
- 照片加一句话、真实生成、完整海报保存与分享。
- 制作等待、记录恢复、失败重试。
- 账号与个人／家庭资料管理、用户确认记忆、资料使用控制。
- 免费体验、限次数包月套餐、购买与扣次记录。
- 必要的内容运营、任务排查、订单与效果统计。

### 后续根据验证结果考虑

- 更多海报风格、节日主题、月度生活合集。
- 更丰富的表达偏好和记忆整理。
- 次数补充包、更多套餐档位。

### 首期不做

珍藏及底部导航、社交广场、关注评论、排行榜、复杂积分、完整聊天陪伴、专业海报编辑器、静默自动记忆、商家知识库、自动导入回忆录、跨账号共享家庭资料。

## 十一、验证指标与评审标准

### 核心观察指标

以“每周生成并保存海报的用户数”为核心价值行为指标，配合满意度和复用判断，不单独用总生成量代表成功。

| 目标 | 指标定义与观察重点 |
|---|---|
| 第一次能完成 | 首次提交用户中成功产出海报的比例；输入到成果的流失与等待时间 |
| 用户认可 | 成功出图后保存比例、明确满意反馈、空泛／不实／语气不喜欢等负反馈 |
| 用户传播 | 分享操作触发率；可追踪分享入口带来的访问与首次制作，不把点击分享等同于实际发送 |
| 用户回来 | 首次出图用户在后续 7 天再次主动发起制作的比例；排除同一失败任务重试 |
| 知识库有价值 | 记忆确认率、资料纠错率；使用资料后的认可和复用变化，不能仅凭相关性宣称因果 |
| 商业可持续 | 免费用尽后的购买转化、套餐使用率、下期复购、退款反馈及成功海报平均成本 |

五类分别查看指标，不仅汇总整体平均。首轮形成真实基线后再设数值目标；当前没有验证数据，不编造提升比例。

### 可进入开发的产品验收口径

- 五类用户都能在同一条简单流程中得到符合场景的回应。
- 空知识库不妨碍首用；已存资料确实可控，不出现跨账号或跨人物混用。
- 生成失败不丢输入、不多扣次数；离开后能找回任务。
- 海报预览与保存结果一致，文字可读，单图、多图和长文案可处理。
- 付费前能看懂次数、期限和使用规则，付费后权益正确到账。
- 到期后仍能查看已有成果与资料，知识库不成为续费绑架条件。
- 分享由用户主动发起，且最终内容可预览。
